## 4. Google contracts and property routing

Use Pydantic v2 models as schema and runtime type source (Python-native equivalent of ADW's schema-derived TypeScript examples), frozen extra-forbid models, bounded strict JSON with duplicate-key rejection and SecretStr/repr suppression. New modules live under src/google_seo_mcp/google_accounts/; each implementation module targets 50–200 lines, splitting by the named boundaries below rather than a generic manager.

### Domain nouns and schemas

- GoogleAccountId: closed values propel-dms and addourteam99; expected email labels are fixed nonsecret configuration, not proof of token ownership.
- GoogleOAuthCredential: version literal integer 1; account_id closed enum; client_id nonempty bounded string; client_secret SecretStr; refresh_token SecretStr; token_uri exactly https://oauth2.googleapis.com/token; scopes exact frozen set above. Reject duplicate account IDs, duplicate credentials, wrong client binding, additional fields, malformed UTF-8 or records above 128 KiB. No arbitrary endpoint/subject fields. Operator-attested identity is explicit in documentation.
- GoogleAccountState: available, missing, invalid, reauthorization_required, provider_unavailable; only safe static codes leave custody. available means local custody/schema readiness, not proof of current Google grants.
- GooglePropertyMembership: provider literal gsc|ga4; exact property_id; account_ids nonempty sorted tuple; GSC permission evidence per account preserved internally. Unverified GSC entries may be listed but never authorize a business read.
- GoogleDiscoverySnapshot: provider; credential_generation; collected_at monotonic timestamp; memberships; per_account_status; complete bool. Complete only when both account attempts and all available provider pages succeed and validate. GSC sites.list has no page contract; GA4 accountSummaries pager must be exhausted. Never invent GSC pagination.
- GoogleAccountClients: private account-bound bundle; credentials and mutable SDK transports never serialized. Client/session/cache key is account_id + credential_generation + provider. Explicit per-account locks cover refresh AND SDK calls including pager consumption, not just construction, because httplib2 transports are not thread-safe.

### Interfaces and operation signatures

- IGoogleCredentialLoader.load_accounts() -> tuple[GoogleOAuthCredential, GoogleOAuthCredential]; local custody only, no network/browser or ambient credentials.
- IGoogleAccountClients.call(account_id, provider, operation) -> validated operation value; executes only inside that identity's lock and generation, with bounded transport timeout.
- IGooglePropertyDiscovery.discover(provider) -> GoogleDiscoverySnapshot; enumerates both identities independently. Request-scoped discovery/admission initially, no cross-request stale access-authority cache. Same-request snapshot can be reused; never treat it as an atomic grant guarantee.
- IGooglePropertyRouter.for_gsc(site_url) and .for_ga4(property_id) -> identity-bound execution adapter; exact membership lookup and read eligibility. Stable preference propel-dms then addourteam99 only among observed eligible accounts. No fallback after an upstream request failure in the initial release: return typed failure, invalidate request state and let the next explicit call rediscover. This avoids hidden duplicate report calls/quota switching.
- Google discovery methods return explicit failure if either account/provider discovery is incomplete; do NOT return a successful data subset. Existing tool result data shapes stay unchanged on complete success. Safe error code agency_discovery_incomplete must survive every hosted boundary: server.py:_safe_tool_error, HostedTool.run, the registered hosted handler and PolicyToolManager.call_tool safe-code allowlists, plus crossplatform/multi_property.py's nested per-property error representation. Audit actual symbol names before conversion; no unreviewed outer-only patch. Preserve existing per-property partial-result semantics while ensuring no business read begins after incomplete agency discovery and no nested result labels that inventory complete. Details use bounded account/provider status, not credential/provider raw errors. Completeness can differ between GSC and GA4; one successful provider is not evidence for the other.

Deduplicate GSC by exact provider siteUrl, keeping domain and URL-prefix properties distinct. Deduplicate GA4 by canonical properties/<digits>, not display names or account names; preserve all parent-account provenance internally, emit the first stable preferred-account row for duplicate resources to retain the current flat data shape. Sort union deterministically. No user-controlled hostname normalization can broaden membership.

Every Google business read revalidates local credential generation and requires fresh request discovery before cached results can be served. Discovery and requested operations share a 60-second request deadline with bounded SDK network timeouts, no unbounded pager or automatic recursive retries. Exhaustion/cycle/repeated page tokens or deadline expiry fail incomplete rather than report a complete union. The initial implementation imposes a local 10,000-property/1,000-page safety ceiling, explicitly not provider quotas; hitting it is incomplete. Keep no property authorization cache across requests initially. Generation changes invalidate clients, schema/data cache partitions and snapshots before admission; re-enrollment normally requires explicit service recreation.

Do not mutate a global current identity or rely on ContextVar propagation into worker threads. Route by explicit property argument at each execution boundary. Cross-platform GSC and GA4 legs resolve independently, so GSC on account A and GA4 on account B is valid. Multi-property thread-pool jobs carry explicit adapters/generations, not process-global switches. Pure transformation functions remain unchanged.

Microsoft GetUserSites returns account-associated sites, including IsVerified=false entries. Definitions:

- Listed: provider returned a structurally valid exact public property URL with strict Boolean verification evidence. Discovery returns valid true AND false entries; false must remain visible as unverified, not silently filtered.
- Eligible for read attempt: the exact requested property is present with strict IsVerified=true in fresh, validated request discovery. This is a local admission rule, not a guarantee that every operation is permitted. Provider authorization remains authoritative.
- False: listed but ineligible. Missing/null/non-Boolean verification or malformed URL: invalid row, no eligibility. Conflicting duplicate entries for the same URL invalidate discovery admission; never let true silently win.
- Missing site or valid unverified site after valid discovery: site_denied without the business-data request. Discovery fault: preserve timeout/rate_limited/access_denied/invalid_response etc.; never mislabel it as empty inventory/site_denied.

Replace BOTH static-file admission and hardcoded set: remove runtime requirement/Compose env for bing_sites_file, drop policy equality and approved_sites filtering, and move site authorization from credential loader into a provider-discovery component. Key-only custody retains protected no-follow directory/leaf and generation checks. Retire the policy document only by an approved operator change; a leftover unreferenced file is not read. Do not weaken the key's custody tests just because the two-document policy disappears.

bing_list_sites performs one discovery call and displays valid provider-listed rows with existing is_verified; retains provider_completeness=unknown because the API offers no pagination/completeness guarantee. It must not apply the analytics default row limit. For a site-specific read, obtain fresh GetUserSites then make the requested read only when eligible. No site fan-out, recursion into the public client, discovery under a held transport semaphore or new cross-request access cache. Local partial/invalid discovery may be displayed explicitly but never admitted as an eligibility snapshot; any dropped/conflicting row denies subsequent business calls with invalid_response.

Preserve existing single-attempt registered behavior, one in-flight HTTP attempt process-wide, 12 attempts per rolling 60 seconds, 15-second per-attempt ceiling, 60-second caller budget and 2 MiB response bound. Discovery consumes the same budget/rate slot as any other attempt; a normal site read now costs two upstream calls. These are local safeguards, not Microsoft quotas. Credential custody and deadline are rechecked before each attempt and after potentially blocking transport entry. No redirects, arbitrary origins, new paid operations or mutation methods. An IsVerified=true entry can still receive access_denied from the business operation. No silent cross-key retry. Read-after-discovery is not an atomic authorization snapshot.
